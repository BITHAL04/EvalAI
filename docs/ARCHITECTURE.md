# Architecture

EvalAI is a modular monolith: one Next.js app, one FastAPI app, one worker process and one Postgres database.

```
Browser ──Clerk session──► Next.js (Vercel)
   │                          │ fetch with Bearer token
   │ signed PUT/GET           ▼
   │                     FastAPI  /api/v1 (Render web)
   ▼                          │  verifies JWT (Clerk JWKS), loads role from DB,
Supabase Storage ◄────────────┤  sets tenant for RLS, enqueues jobs
(private bucket)              ▼
                         Postgres + pgvector (Supabase) ◄──── worker (Render worker)
                                                               │ LangGraph workflows
                                                               ▼
                                                          Gemini API
```

## Repository

| Path | Contents |
|---|---|
| `apps/web` | Next.js App Router UI. Every page fetches from the API; no data is hard-coded. |
| `apps/api/app` | FastAPI: `core` (config, auth, DB, storage, errors), `api/v1` routers, `services` (domain logic), `models`, `schemas`, `worker.py`. |
| `apps/api/alembic` | Migrations. `0001` schema, `0002` least-privilege role, RLS, append-only triggers, reference data. |
| `ai_engine` | Framework-free AI code: provider interface and Gemini implementation, ingestion, retrieval, question generation, rubric engine, handwriting, evaluation, challenge, analytics. It never imports the web app. |
| `scripts` | Seed data, Supabase bucket setup, benchmark runner, e2e stack and the clearly labelled test doubles in `dev_stubs`. |

## Decisions

**Tenancy.** Every institution-owned table has `institution_id` and a Postgres RLS policy keyed on `app.institution_id`, which the API sets per transaction from the authenticated membership. The API connects as `evalai_app` (no BYPASSRLS), so a forgotten `WHERE` cannot leak another institution's rows. Every query also filters explicitly. Students are further restricted to their own rows in code.

**Identity.** Clerk handles sign-in. The API trusts only a verified token's `sub` and verified email. Roles and institution membership live in our database and change only through admin actions or invitations.

**Jobs.** Long AI work runs in a separate worker that claims rows from `background_jobs` with `SELECT … FOR UPDATE SKIP LOCKED`. Jobs survive restarts, a stuck job is reclaimed after `WORKER_LOCK_TIMEOUT_SECONDS`, transient failures retry with backoff, and an idempotency key prevents duplicate work. Evaluation commits per question, so a retry resumes instead of re-marking. On final failure every domain object is left in a visible, retryable state.

**Storage.** One private bucket. The browser uploads and downloads with short-lived signed URLs. Object paths are generated by the server and sealed into signed tokens, so clients cannot register arbitrary objects. Original answer pages are rendered once and kept for every later review.

**Replaceable parts.** `AIProvider` (generate structured / embed), `StorageProvider` (Supabase or local) and the retrieval search function are interfaces. Changing the model is an environment variable.

**Grading integrity.**
- Nothing is visible to students until a teacher approves the answer sheet and publishes results.
- Marks are summed from per-criterion scores; the database rejects marks outside `0..max`.
- `evaluation_versions`, `challenge_decisions` and `audit_logs` are append-only, enforced by triggers and revoked privileges.
- Approved rubrics are immutable; a change creates the next version.
